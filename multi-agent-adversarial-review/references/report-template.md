# 报告模板 — multi-agent-adversarial-review

每次审查报告都使用此结构。填写每节；对抗记录必须完整。

```markdown
# 对抗式审查报告 — <对象>

## 1. 范围与基线
- 审查对象：<diff / commit / 分支 / 设计文档>
- 基线状态：<工作区状态、相关文件>
- 强度：<视角数> × <R> 评审 + <挑战者数>；用户指定：<是/否，指定了什么>

## 2. 视角分配记录
| 视角 | 评审者 | 分配理由 | 备注 |
|---|---|---|---|
| ... | ... | ... | ... |
- 超出推荐列表的新增视角：<列表 + 理由>

## 3. 评审发现
| # | 发现 | 代码位置 | 触发路径 | 证据 | 初判严重度 |
|---|---|---|---|---|---|
| ... | ... | ... | ... | ... | ... |

## 4. 对抗记录
| 攻击 # | 目标发现 | 攻击点 | 辩论轮次 | 结果（共识 / 争议 / 驳回） | 理由 |
|---|---|---|---|---|---|
| ... | ... | ... | ... | ... | ... |

## 5. 最终分级表
| # | 发现 | 最终严重度 | 来源（评审者 / 挑战者 / 主 agent） | 是否争议项 |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

## 6. 未验证项
- <结论> 依赖运行验证：<未运行什么及原因>

## 7. 裁决摘要
- 最终结论：...
- 建议下一步（仅评审意见）：...

## 用户假设裁决
- 假设：<用户原述>
- 裁决：证实 / 证伪 / 证据不足
- 证据链：<专项评审者的证据>
- 对抗结果：<是否被攻击；结果>

## 范围边界
- 已审：...
- 未审：<明确列表，例如仅静态审查，未做运行验证；未覆盖模块 X>
```

## 命名

`adversarial-review-<对象标识>-<YYYYMMDD>.md`，对象标识为 commit 短 hash、分支名或文档名。
